# Project principles (read before every spec, prompt, or code change)

Team standing rules for the Diligent Track 2 sanctions-screening resolver. These override convenience.

1. **The job:** the system reviews an alert, makes a decision for every hit (SAME_ENTITY / DIFFERENT_ENTITY / REVIEW), and gives a reason for it.
2. **A bad decision is worse than no decision.** This is a principle, not just a scoring trick. When evidence does not settle it, answer REVIEW. Clear (DIFFERENT_ENTITY) only on an explicit SOP contradiction; confirm (SAME_ENTITY) only on explicit agreement with nothing contradicting.
3. **Explainability is a primary target.** Every decision must be traceable: the reason code, the minimal cited evidence IDs, and the resolved customer_record_id, and the rule path that led there.
4. **Reasons must be precise.** 2–4 sentences, using this hit's own facts (names, DOBs, countries, dates, record IDs). No generic boilerplate, no hedging, no facts that were not used.
5. **Reproducibility is a primary target.** Diligent runs the system 5 times; decision and reason_code must be identical every run. Decision path is deterministic code. Any model call (OpenRouter only, OPENROUTER_API_KEY) is temperature 0, cached, and has a deterministic template fallback; it never changes the decision.
6. **The data is anomaly-detection-shaped.** Most hits are routine; true matches and hard cases are rare. Don't assume errors are common; mine the data carefully to understand the real patterns and surface useful signals before writing rules.
7. **Study the data deeply.** There is a lot of information across Alerts, Hits, Customers, Accounts, Onboarding, KYC checks, Notes and Search results. Mine it, and bring useful findings to the surface (documented in DATA_NOTES.md).
8. **Models.** The team uses Jev (TypeSafe AI, a System One decision model returning typed decisions with calibrated confidence), available on OpenRouter as `typesafe/jev-router`, so it is allowed in `system/run`. Use it only for narrow typed sub-questions the rules cannot settle (for example, whether a search snippet describes the same listing type and country, or which birth year a note implies), never as a free-form decider. Act on its answer only above a confidence threshold. Clearing needs about 95% or better, the cost-matrix break-even of 60/63. Below that, `REVIEW`. Cache every call by input hash. A hash-keyed cache is fine to commit only if it contains no dev records; do not commit `dev/` data. Verify identical outputs across 5 runs. With no `OPENROUTER_API_KEY`, or on any error, fall back to the deterministic rules. Grok via OpenRouter (`x-ai/grok-4.x`) is only for writing precise reasons, under the same cache, threshold, and fallback rules. Jev and Grok must still obey rules 2–5.
9. **Hard constraints from the brief:** `system/run <data folder> <output file>`; Python 3 / Node stdlib or shell only; reads only that folder; LLM only via OpenRouter; under 30 minutes; never commit dev/ data or keys; last commit before the deadline is scored.
